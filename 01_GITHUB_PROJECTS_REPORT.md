## 🎮 Game Development Highlights

### How_Ball - Technical Deep Dive

#### Game Architecture
```
GameManager (Lifecycle Control)
    ├── Scene (3D Context)
    │   ├── Camera & Lighting
    │   ├── Ball (Player Entity)
    │   ├── Road (Infinite Scroll)
    │   └── ObstacleManager
    ├── InputManager (Controls)
    └── UIOverlay (Score, UI)
```

#### Core Systems
1. **Fixed Timestep Loop** - Ensures consistent physics regardless of frame rate
2. **ECS Pattern** - Separates data (components) from behavior (systems)
3. **Collision Detection** - AABB (Axis-Aligned Bounding Box) implementation
4. **Procedural Generation** - Infinite road segments with random obstacles
5. **Input System** - Unified handling for keyboard and touch events

#### Performance Optimizations
- Object pooling for obstacles (reduce garbage collection)
- Frustum culling (only render visible objects)
- Level of detail (LOD) for distant objects
- Batched rendering where possible
- State updates batched per frame

## 💡 Notable Technical Decisions

### Why React Three Fiber?
- Declarative 3D programming matches React mental model
- Component reusability for 3D objects
- Hooks for animation and interaction
- Better integration with React ecosystem
- Smaller learning curve than raw Three.js

### Why Zustand over Redux?
- Minimal boilerplate (< 50 lines vs > 200)
- No context providers needed
- Better TypeScript support
- Simpler API for game state updates
- Smaller bundle size (~1KB vs ~20KB)

### Why Next.js for Games?
- Server-side rendering for SEO
- Built-in routing for multi-page games
- API routes for leaderboards/auth
- Automatic code splitting
- Vercel deployment optimization
- Easy to add non-game pages (landing, about)

### Why Snowflake for Logpose?
- Scalable cloud data warehouse
- SQL familiar interface
- Automatic scaling
- Good for analytics queries
- Modern cloud-native architecture
